## 3. 요구사항

과제는 크게 **두 개의 축**으로 구성됩니다. 두 축 모두 필수입니다.

### 3-1. SNS 프로젝트 (기능 구현)

아래 기능은 **모두 필수**입니다.

| 구분 | 기능 | 설명 |
|------|------|------|
| 계정 | 회원가입 | 신규 사용자 등록 |
| 계정 | 로그인 | 인증 및 세션 유지 |
| 소셜 | 팔로우 / 팔로잉 | 다른 사용자 팔로우, 팔로워·팔로잉 목록 확인 |
| 콘텐츠 | 게시글 작성 | 게시글 생성 및 피드 노출 |
| 콘텐츠 | 댓글 | 게시글에 댓글 작성 |
| 콘텐츠 | 대댓글 | 댓글에 답글 작성 (계층 구조) |

**디자인 요구사항**

- AI가 만든 듯한 획일적인 느낌(과도한 그라데이션, 정형화된 카드 레이아웃, 의미 없는 장식 등)을 피해 주세요.
- 깔끔한 레이아웃과 일관된 타이포그래피, 여백을 갖춰야 합니다.
- 사용자의 행동에 반응하는 인터랙션(전환, 피드백, 상태 표시 등)이 자연스럽게 녹아 있어야 합니다.

**배포 요구사항**

- 실제 접속 가능한 URL로 배포되어야 합니다. (Vercel, Netlify, Cloudflare, AWS, Railway, Fly.io 등 자유)
- 심사자가 직접 회원가입 → 로그인 → 게시글 작성 → 댓글/대댓글 → 팔로우 흐름을 끝까지 체험할 수 있어야 합니다.

### 3-2. 하네스(Harness) 세팅

**하네스란** 개발자(또는 AI 에이전트)가 프로젝트에서 **일관된 방식으로, 안정적으로** 기능을 개발하고 유지보수할 수 있도록 감싸는 개발 환경과 규칙의 집합입니다.

단순히 린터를 설치하는 것을 넘어, **"이 프로젝트에 새로운 사람이 합류해도 같은 품질로 기능을 추가할 수 있는가?"** 라는 질문에 답할 수 있어야 합니다.

하네스에 포함할 만한 요소의 예시는 다음과 같습니다. 모든 항목이 필수는 아니며, **프로젝트에 필요한 것을 판단해 구성하는 것 자체가 평가 대상**입니다.

- 프로젝트 컨벤션과 아키텍처 규칙을 담은 문서 (예: `CLAUDE.md`, `AGENTS.md`, `CONTRIBUTING.md`)
- 코드 스타일 자동화 (Lint, Formatter, 타입 검사)
- 테스트 환경 (단위 / 통합 / E2E 중 프로젝트에 맞는 수준)
- Git 훅 또는 CI 파이프라인 (커밋·PR 시 자동 검증)
- 배포 자동화 (main 브랜치 푸시 시 자동 배포 등)
- 폴더 구조와 모듈 경계에 대한 규칙
- 환경 변수, 시크릿 관리 방식
- AI 에이전트를 활용한 개발 워크플로우 (프롬프트, 스킬, 커맨드 등)

**하네스가 실제로 동작하는지를 보여주세요.** 예를 들어, 하네스 세팅 이후 기능을 추가한 커밋 히스토리가 있다면 하네스의 효과를 판단하기 훨씬 수월합니다.

## 4. 제출 방법

### 4-1. 제출물

아래 두 가지 링크를 제출해 주세요.

1. **GitHub 저장소 링크** (Public 또는 심사자 초대)
2. **배포된 사이트 링크** (실제 접속 및 사용 가능해야 함)

### 4-2. 저장소에 반드시 포함해야 하는 것

```
your-repo/
├── README.md          # 프로젝트 소개, 실행 방법, 하네스 설명, 기술적 의사결정
├── exports/           # AI 대화 기록 내보내기 파일 (필수)
│   └── ...
└── ...                # 프로젝트 소스
```

**`README.md`에는 다음 내용을 포함해 주세요.**

- 프로젝트 개요 및 배포 URL
- 로컬 실행 방법
- 기술 스택 선택 이유
- 하네스 구성 설명 (무엇을, 왜 세팅했는지)
- 구현 중 내린 주요 기술적 의사결정과 트레이드오프
- 시간이 더 있었다면 개선했을 부분

### 4-3. AI 대화 기록 내보내기 (`exports/`)

과제 진행 중 AI 도구(Claude Code, Cursor, ChatGPT 등)와 나눈 대화는 **`export` 명령어를 통해 내보낸 파일**을 저장소의 **`exports/` 폴더**에 포함해 주세요.

- AI를 활용하는 것은 **권장**됩니다. 감점 요소가 아닙니다.
- 대화 기록은 여러분이 **어떤 질문을 던지고, 어떻게 판단하고, 무엇을 검증했는지**를 보기 위한 자료입니다.
- 여러 세션이 있다면 파일을 나누어 저장해도 괜찮습니다.
- 대화 기록에 개인정보나 시크릿(API 키 등)이 포함되지 않도록 확인해 주세요.

> Claude Code 사용 시: 세션 내에서 `/export` 명령어로 대화를 파일로 내보낼 수 있습니다.

## 5. 평가 기준

| 영역 | 비중 | 무엇을 보는가 |
|------|------|--------------|
| **기능 완성도** | 30% | 필수 기능이 빠짐없이 동작하는가. 엣지 케이스(빈 상태, 에러, 권한)를 처리했는가 |
| **하네스 완성도** | 30% | 일관성과 안정성을 담보하는 환경이 구성되었는가. 실제로 동작하며 유지보수에 기여하는가 |
| **디자인 & 인터랙션** | 20% | 고객 요청에 부합하는가. AI 티 없이 깔끔하고 인터랙션이 자연스러운가 |
| **속도 & 출시 역량** | 10% | 기한 내 배포까지 완료했는가. 우선순위 판단이 적절했는가 |
| **의사결정 & 커뮤니케이션** | 10% | README와 AI 대화 기록에서 판단 근거가 드러나는가. 트레이드오프를 인식하고 있는가 |

**가점 요소**

- 하네스 세팅 이후 실제 기능을 추가한 커밋 흐름이 명확히 보이는 경우
- 테스트가 실제 리스크 지점을 커버하는 경우
- 배포 자동화가 구성되어 main 푸시만으로 배포되는 경우

**감점 요소**

- 배포되지 않았거나 접속 불가한 경우
- 필수 기능 누락
- `exports/` 폴더 누락
- 저장소에 시크릿(API 키, DB 비밀번호 등)이 커밋된 경우
